1. Introduction to DBMS

What is Data?

Data means raw facts and figures that can be processed to obtain useful information. Examples include student names, marks, addresses and phone numbers.

What is a Database?

A database is an organized collection of related data that can be stored, accessed, managed and updated easily.

What is DBMS?

DBMS stands for Database Management System. It is software used to create, store, organize, retrieve and manage data in a database.

Examples of DBMS

  • MySQL
  • Oracle Database
  • Microsoft SQL Server
  • PostgreSQL
  • Microsoft Access

Advantages of DBMS

  • Reduces data duplication.
  • Improves data security.
  • Provides data sharing.
  • Maintains data consistency.
  • Supports backup and recovery.
  • Provides easy data access.

Disadvantages of DBMS

  • High installation and maintenance cost.
  • Requires trained database administrators.
  • May require more memory and storage.
  • System failure can affect many users.

Database Users

  • Database Administrator (DBA): Manages and controls the database.
  • Database Designers: Design the database structure.
  • Application Programmers: Develop database applications.
  • End Users: Use database applications to access information.

Responsibilities of DBA

  • Creating and maintaining databases.
  • Managing user permissions.
  • Providing database security.
  • Taking backups and recovering data.
  • Monitoring database performance.

2. Data Models

A data model describes how data is organized, stored and related in a database.

Hierarchical Data Model

In this model, data is arranged in a tree-like structure. Each child record has only one parent.

Example: A college contains departments, and each department contains students.

Network Data Model

Data is represented using records and links. A child record can have multiple parent records.

Relational Data Model

Data is stored in tables consisting of rows and columns. Tables can be connected using keys.

Object-Oriented Data Model

Data is represented as objects containing attributes and methods. It supports object-oriented concepts.

The relational model is widely used because data can be organized into tables and accessed using SQL.

3. Keys in DBMS

A key is an attribute or a group of attributes used to identify records uniquely or establish relationships between tables.

Primary Key

A primary key uniquely identifies each row in a table. It cannot contain duplicate or NULL values.

Candidate Key

A candidate key is an attribute or combination of attributes that can uniquely identify a record.

Super Key

A super key is any set of one or more attributes that uniquely identifies a row.

Foreign Key

A foreign key is an attribute in one table that refers to a primary key in another table.

Composite Key

A composite key consists of two or more attributes used together to identify a record uniquely.

Alternate Key

A candidate key that is not selected as the primary key is called an alternate key.

Unique Key

A unique key constraint ensures that values in a column or group of columns are unique.

Surrogate Key

A surrogate key is an artificially created identifier, such as an automatically generated ID.

Database Constraints

  • PRIMARY KEY – Uniquely identifies each record.
  • FOREIGN KEY – Maintains relationships between tables.
  • UNIQUE – Prevents duplicate values.
  • NOT NULL – Does not allow empty NULL values.
  • CHECK – Ensures values satisfy a condition.

4. Entity Relationship Model

The Entity Relationship (ER) model is used to represent the structure of a database through entities, attributes and relationships.

Entity

An entity is a real-world object that can be identified separately.

Example: Student, Teacher, Employee.

Entity Set

A collection of similar entities is called an entity set.

Attributes

Attributes describe the properties of an entity.

Example: Student_ID, Name, Age and Address.

Types of Attributes

  • Simple Attribute – Cannot be divided further.
  • Composite Attribute – Can be divided into smaller parts.
  • Single-valued Attribute – Has one value.
  • Multi-valued Attribute – Can have multiple values.
  • Derived Attribute – Calculated from another attribute.
  • Key Attribute – Uniquely identifies an entity.

Relationship

A relationship represents an association between entities.

Types of Relationships

  • One-to-One (1:1)
  • One-to-Many (1:M)
  • Many-to-One (M:1)
  • Many-to-Many (M:N)

ER Diagram Symbols

  • Rectangle – Entity.
  • Oval – Attribute.
  • Diamond – Relationship.
  • Double Rectangle – Weak Entity.
  • Underlined Attribute – Key Attribute.

Weak Entity

A weak entity cannot be uniquely identified by its own attributes alone. It depends on another entity for identification.

Extended ER Features

  • Specialization – Dividing a higher-level entity into lower-level entities.
  • Generalization – Combining similar lower-level entities into a higher-level entity.
  • Aggregation – Treating a relationship as a higher-level entity.
  • Inheritance – Lower-level entities inherit properties from higher-level entities.

5. Relational Model

The relational model stores data in the form of tables called relations.

Important Terms

  • Relation – A table.
  • Tuple – A row in a table.
  • Attribute – A column in a table.
  • Domain – The set of valid values for an attribute.
  • Degree – Number of columns in a relation.
  • Cardinality – Number of rows in a relation.
  • Relational Schema – Structure of a relation.

Example: Student Table

Student_ID   Name       Marks
101          Sanjay     85
102          Ravi       90
103          Kumar      78

Relational Algebra

Relational algebra is a procedural query language used to perform operations on relations.

Selection (σ)

Selects rows that satisfy a given condition.

σ Marks > 80 (Student)

Projection (π)

Selects specific columns from a relation.

π Name, Marks (Student)

Union (∪)

Combines the rows of two compatible relations and removes duplicate rows.

Intersection (∩)

Returns rows that are common to both relations.

Set Difference (−)

Returns rows present in the first relation but not in the second.

Cartesian Product (×)

Combines every row of one relation with every row of another relation.

Join (⋈)

Combines related rows from two or more tables based on a condition.

Division (÷)

Used to find records associated with all records in another relation.

6. Introduction to SQL

SQL stands for Structured Query Language. It is used to create, retrieve, modify and manage data in relational databases.

Types of SQL Commands

  • DDL – Data Definition Language.
  • DML – Data Manipulation Language.
  • DQL – Data Query Language.
  • DCL – Data Control Language.
  • TCL – Transaction Control Language.

DDL Commands

DDL commands are used to define or modify database structures.

CREATE TABLE Student (
    ID INT PRIMARY KEY,
    Name VARCHAR(50),
    Marks INT
);

ALTER TABLE Student
ADD City VARCHAR(30);

TRUNCATE TABLE Student;

DROP TABLE Student;

DML Commands

DML commands are used to insert, update and delete records.

INSERT INTO Student
VALUES (101, 'Sanjay', 85);

UPDATE Student
SET Marks = 90
WHERE ID = 101;

DELETE FROM Student
WHERE ID = 101;

SELECT Command

The SELECT command retrieves data from a table.

SELECT * FROM Student;

SELECT Name, Marks
FROM Student;

SELECT *
FROM Student
WHERE Marks > 80;

Aggregate Functions

  • COUNT() – Counts records.
  • SUM() – Calculates the total.
  • AVG() – Calculates the average.
  • MAX() – Finds the highest value.
  • MIN() – Finds the lowest value.
SELECT COUNT(*) FROM Student;
SELECT SUM(Marks) FROM Student;
SELECT AVG(Marks) FROM Student;
SELECT MAX(Marks) FROM Student;
SELECT MIN(Marks) FROM Student;

Logical Operators

  • AND – All conditions must be true.
  • OR – At least one condition must be true.
  • NOT – Reverses a condition.
SELECT * FROM Student
WHERE Marks > 70 AND City = 'Mysuru';

SQL Predicates

-- LIKE
SELECT * FROM Student
WHERE Name LIKE 'S%';

-- BETWEEN
SELECT * FROM Student
WHERE Marks BETWEEN 60 AND 90;

-- IN
SELECT * FROM Student
WHERE City IN ('Mysuru', 'Bengaluru');

-- DISTINCT
SELECT DISTINCT City FROM Student;

GROUP BY

GROUP BY groups rows having the same values in specified columns.

SELECT City, COUNT(*)
FROM Student
GROUP BY City;

HAVING

HAVING is used to apply conditions to groups.

SELECT City, COUNT(*)
FROM Student
GROUP BY City
HAVING COUNT(*) > 2;

ORDER BY

ORDER BY sorts records in ascending or descending order.

SELECT * FROM Student
ORDER BY Marks DESC;
SQL syntax can vary slightly between database systems. For example, LIMIT is commonly used in MySQL and PostgreSQL, while TOP is used in SQL Server.

7. SQL Joins

A join is used to combine records from two or more tables based on a related column.

INNER JOIN

Returns only matching records from both tables.

SELECT Student.Name, Department.DeptName
FROM Student
INNER JOIN Department
ON Student.DeptID = Department.DeptID;

LEFT OUTER JOIN

Returns all records from the left table and matching records from the right table. Unmatched right-side values appear as NULL.

RIGHT OUTER JOIN

Returns all records from the right table and matching records from the left table.

FULL OUTER JOIN

Returns matching and non-matching records from both tables. Support depends on the database system.

NATURAL JOIN

Automatically joins tables using columns with the same names and compatible data types.

EQUI JOIN

A join that uses the equality operator (=) to match rows from tables.

8. Views in DBMS

A view is a virtual table created from the result of an SQL query. It usually stores the query definition rather than a separate copy of the data.

Advantages of Views

  • Improves data security.
  • Simplifies complex queries.
  • Provides customized data presentation.
  • Can hide unnecessary columns.

Creating a View

CREATE VIEW StudentView AS
SELECT ID, Name
FROM Student;

Displaying a View

SELECT * FROM StudentView;

Updating a View

CREATE OR REPLACE VIEW StudentView AS
SELECT ID, Name, Marks
FROM Student;

Deleting a View

DROP VIEW StudentView;
Whether a view can be updated depends on its definition and the database system.

9. Database Normalization

Normalization is the process of organizing data in a database to reduce data redundancy and avoid insertion, deletion and update anomalies.

Database Anomalies

  • Insertion Anomaly – Difficulty inserting data without other unnecessary data.
  • Update Anomaly – The same information must be updated in multiple places.
  • Deletion Anomaly – Deleting one record may accidentally remove useful information.

Functional Dependency

A functional dependency exists when one attribute determines the value of another attribute.

Student_ID → Student_Name

This means Student_ID determines Student_Name.

First Normal Form (1NF)

  • Each cell must contain a single value.
  • No repeating groups are allowed.
  • Each record should be identifiable.

Second Normal Form (2NF)

  • The table must already be in 1NF.
  • Every non-key attribute must depend on the whole candidate key.
  • Partial dependency must be removed.

Third Normal Form (3NF)

  • The table must already be in 2NF.
  • Transitive dependencies of non-key attributes must be removed.

Boyce-Codd Normal Form (BCNF)

A relation is in BCNF when every determinant is a super key.

Database Decomposition

Decomposition means dividing a large relation into smaller relations to reduce redundancy and improve database design.

Transitive Dependency

A transitive dependency occurs when a non-key attribute depends on another non-key attribute instead of directly depending on the key.

Normalization helps maintain consistency and reduces unnecessary duplication of data.

10. Transaction Processing

A transaction is a logical unit of database work that contains one or more operations.

Example

Transferring money from one bank account to another involves deducting money from one account and adding it to another.

ACID Properties

  • Atomicity – A transaction is completed fully or not at all.
  • Consistency – A transaction keeps the database in a valid state.
  • Isolation – Concurrent transactions should not interfere incorrectly with each other.
  • Durability – Committed changes remain saved even after a failure.

Transaction States

  • Active – Transaction is executing.
  • Partially Committed – Final operation has been executed.
  • Committed – Transaction completed successfully.
  • Failed – Transaction cannot continue.
  • Aborted – Transaction has been rolled back.

Single-User Database System

A single-user database system allows only one user to access the database at a time.

Multi-User Database System

A multi-user database system allows multiple users to access the database simultaneously.

Concurrency Control

Concurrency control manages simultaneous transactions to maintain database consistency.

Lost Update Problem

Occurs when two transactions update the same data and one update overwrites the other.

Dirty Read Problem

Occurs when a transaction reads data modified by another transaction that has not yet committed.

Database Failures

  • Transaction Failure – A transaction cannot complete.
  • System Crash – Hardware or software failure stops the system.
  • Media Failure – Storage device failure causes data loss.
  • Communication Failure – Network problems interrupt database operations.

Database Storage

Database storage involves saving database files, records, indexes and other information on storage devices.

Database File Operations

  • Creating database files.
  • Reading and writing records.
  • Updating stored information.
  • Deleting records.
  • Backing up and restoring files.

Database Security

  • Authentication – Verifying user identity.
  • Authorization – Controlling user permissions.
  • Encryption – Protecting data using encryption.
  • Backup – Keeping copies of important data.
  • Auditing – Monitoring database activities.
