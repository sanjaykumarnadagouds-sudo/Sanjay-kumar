1. Introduction to Cloud Computing

1.1 What is Cloud Computing?

Cloud Computing is the delivery of computing services such as servers, storage, databases, networking and software over the Internet.

Instead of buying and maintaining their own physical servers, users can access computing resources from cloud service providers whenever required.

Examples: Google Drive, Microsoft OneDrive, Gmail and Amazon Web Services.

1.2 Definition of Cloud Computing

Cloud Computing is a technology that provides on-demand access to shared computing resources over a network, usually the Internet.

Users can access these resources without managing all the underlying hardware and infrastructure themselves.

1.3 Characteristics of Cloud Computing

  • On-demand self-service: Users can obtain computing resources whenever required.
  • Broad network access: Services can be accessed through the Internet using different devices.
  • Resource pooling: Computing resources are shared among multiple users.
  • Rapid elasticity: Resources can be increased or decreased quickly.
  • Measured service: Resource usage can be monitored and measured.

1.4 History and Evolution of Cloud Computing

Cloud Computing developed from earlier computing technologies.

  • Mainframe computing: Multiple users shared a central computer.
  • Time-sharing: Many users shared computing resources at different times.
  • Distributed computing: Multiple computers worked together.
  • Virtualization: One physical machine could run multiple virtual machines.
  • Internet development: Faster networks made remote computing services practical.
  • Modern cloud: Providers began offering storage, servers, platforms and applications over the Internet.

1.5 Cloud Computing Architecture

Cloud architecture describes the components that work together to provide cloud services.

  • Front end: The user's device, browser or application used to access cloud services.
  • Back end: Cloud servers, storage, databases and management systems.
  • Network: Connects users to cloud resources.
  • Management: Controls resource allocation, monitoring and service operation.
  • Security: Protects cloud applications, accounts and data.
User Device → Internet → Cloud Platform → Servers / Storage / Applications

1.6 Benefits of Cloud Computing

  • Reduces the need to purchase expensive hardware.
  • Provides access from different locations.
  • Allows easy expansion of resources.
  • Supports backup and recovery.
  • Provides flexible payment options.
  • Supports collaboration and file sharing.
  • Reduces some infrastructure maintenance work.

1.7 Challenges of Cloud Computing

  • Internet dependency: Many cloud services require a reliable network connection.
  • Security risks: Data and accounts must be protected from attacks.
  • Privacy: Sensitive information needs proper protection.
  • Downtime: Provider outages can interrupt services.
  • Vendor lock-in: Moving from one provider to another may be difficult.
  • Cost management: Poor resource management can increase expenses.
  • Compliance: Organizations must follow applicable laws and regulations.

2. Cloud Service and Deployment Models

2.1 Cloud Service Models

Cloud service models describe the type of computing resources provided to users.

The three major service models are IaaS, PaaS and SaaS.

2.2 Infrastructure as a Service (IaaS)

IaaS provides basic computing infrastructure such as virtual machines, storage and networking over the Internet.

Users can install operating systems and applications and manage many software settings themselves.

Examples:

  • Amazon EC2
  • Google Compute Engine
  • Microsoft Azure Virtual Machines

Advantages: Flexible infrastructure, scalability and reduced need to purchase physical servers.

2.3 Amazon EC2

Amazon Elastic Compute Cloud (EC2) is a service provided by Amazon Web Services (AWS). It allows users to create and run virtual servers called instances.

  • Launch virtual machines.
  • Select computing capacity.
  • Choose operating systems.
  • Increase or decrease resources.
  • Connect applications to cloud infrastructure.

2.4 Google Compute Engine

Google Compute Engine is a Google Cloud service that provides virtual machines for running applications and workloads.

Users can select machine types, operating systems, storage and networking configurations.

2.5 Microsoft Azure Virtual Machines

Azure Virtual Machines is a cloud service that provides virtual computers on Microsoft's Azure platform.

It supports different operating systems and allows users to configure computing resources according to their requirements.

2.6 Platform as a Service (PaaS)

PaaS provides a platform and environment for developers to build, test, deploy and manage applications.

The cloud provider manages much of the underlying infrastructure and platform environment.

Examples:

  • AWS Elastic Beanstalk
  • Google App Engine
  • Azure App Services

Advantages: Simplifies application development, reduces infrastructure management and supports faster deployment.

2.7 AWS Elastic Beanstalk

AWS Elastic Beanstalk is a service that helps developers deploy and manage applications on AWS.

It handles several deployment-related tasks, including provisioning and monitoring supported application environments.

2.8 Google App Engine

Google App Engine is a platform for developing and hosting applications on Google Cloud.

Developers can deploy applications without directly managing all the server infrastructure.

2.9 Azure App Services

Azure App Service is a platform for building, deploying and hosting web applications and APIs using Microsoft Azure.

It supports application deployment and managed hosting features.

2.10 Software as a Service (SaaS)

SaaS provides ready-to-use software applications over the Internet. Users generally access the software through a web browser or application.

The service provider manages the application and underlying infrastructure.

Examples:

  • Google Workspace
  • Microsoft 365
  • Salesforce
  • Online email services

Advantages: Easy access, automatic updates and reduced software installation and maintenance.

2.11 Google Workspace

Google Workspace is a collection of cloud-based productivity and collaboration applications.

It includes services such as Gmail, Google Drive, Docs, Sheets and Meet.

2.12 Microsoft Office 365 / Microsoft 365

Microsoft 365 provides productivity and collaboration applications and cloud services.

Examples include Word, Excel, PowerPoint, Outlook, OneDrive and Teams, depending on the subscription.

2.13 Difference Between IaaS, PaaS and SaaS

  • IaaS: Provides virtual infrastructure such as servers, storage and networks.
  • PaaS: Provides a platform for developing and deploying applications.
  • SaaS: Provides ready-to-use software applications.
IaaS Example: Amazon EC2
PaaS Example: Google App Engine
SaaS Example: Google Workspace

2.14 Cloud Deployment Models

Deployment models describe how cloud infrastructure is owned, managed and made available to users.

The major deployment models are Public Cloud, Private Cloud, Hybrid Cloud and Community Cloud.

2.15 Public Cloud

A public cloud is a cloud environment provided by a service provider over the Internet to multiple customers.

Advantages:

  • Easy access.
  • Flexible resource usage.
  • No need to maintain physical cloud infrastructure.
  • Suitable for many different workloads.

Example: Public cloud services offered by AWS, Microsoft Azure and Google Cloud.

2.16 Private Cloud

A private cloud is a cloud environment dedicated to a single organization.

It may be managed by the organization or by a service provider.

Advantages: Greater control over configuration, access and organizational requirements.

Example: A company operating its own private cloud infrastructure.

2.17 Hybrid Cloud

A hybrid cloud combines private cloud infrastructure with public cloud services, allowing data and applications to work across both environments.

Example: A company stores sensitive data in its private environment and uses public cloud resources for additional computing capacity.

2.18 Community Cloud

A community cloud is shared by organizations that have common requirements, such as security, policy or compliance needs.

Example: Multiple educational or research institutions sharing cloud infrastructure for common projects.

3. Virtualization and Cloud Storage

3.1 Introduction to Virtualization

Virtualization is a technology that creates virtual versions of computing resources such as servers, operating systems, storage and networks.

It allows multiple virtual environments to run on a single physical machine.

Example: Running Windows and Linux virtual machines on one physical computer.

3.2 Server Virtualization

Server virtualization divides one physical server into multiple virtual servers. Each virtual server can run its own operating system and applications.

Benefits:

  • Better hardware utilization.
  • Reduced physical server requirements.
  • Flexible resource allocation.
  • Easy creation and management of virtual machines.

3.3 Network Virtualization

Network virtualization creates logical network resources that operate independently of the underlying physical network hardware.

It helps administrators create and manage virtual networks, switches and network connections.

3.4 Storage Virtualization

Storage virtualization combines storage resources from multiple physical devices and presents them as a logical storage system.

It makes storage management easier and can improve resource utilization.

3.5 What is a Hypervisor?

A hypervisor is software or firmware that creates and manages virtual machines. It allows multiple operating systems to share the resources of one physical computer.

Types of Hypervisors:

  • Type 1 – Bare-metal: Runs directly on physical hardware.
  • Type 2 – Hosted: Runs as an application on an existing operating system.

3.6 VMware

VMware provides virtualization products that help create and manage virtual machines and virtual infrastructure.

Its tools are used in desktop virtualization and data centre environments.

3.7 Microsoft Hyper-V

Microsoft Hyper-V is a virtualization technology that allows users to create and manage virtual machines on supported Windows systems and Windows Server editions.

It is commonly used for server and desktop virtualization.

3.8 KVM Hypervisor

KVM stands for Kernel-based Virtual Machine. It is a virtualization technology built into the Linux kernel.

It allows Linux systems to run virtual machines using hardware virtualization support.

3.9 Cloud Storage

Cloud storage is a service that allows users to store data on remote servers managed by a cloud provider and access it through a network.

Examples: Google Drive, OneDrive, Dropbox and Amazon S3.

Benefits:

  • Access files from different devices.
  • Share files with other users.
  • Support backup and recovery.
  • Expand storage capacity as required.

3.10 Cloud Storage Solutions

Cloud providers offer different storage solutions based on the type of data and access requirements.

  • Object storage: Stores data as objects with metadata.
  • Block storage: Stores data in fixed-size blocks, often used with virtual machines.
  • File storage: Stores data in files and folders.

3.11 Amazon S3

Amazon Simple Storage Service (Amazon S3) is an object storage service provided by AWS.

  • Stores files as objects.
  • Organizes objects in buckets.
  • Supports data backup and storage.
  • Provides access management features.
  • Can store large amounts of data.

3.12 Azure Blob Storage

Azure Blob Storage is Microsoft's object storage service for storing large amounts of unstructured data.

It can store documents, images, videos, backups and other files.

3.13 Google Cloud Storage

Google Cloud Storage is an object storage service provided by Google Cloud.

It is used for storing and retrieving files, backups, application data and other digital content.

3.14 Cloud Database Services

Cloud database services provide databases hosted and managed on cloud infrastructure.

They help organizations store, organize, retrieve and manage data without maintaining all database hardware themselves.

Benefits: Scalability, remote access, managed maintenance and backup options.

3.15 Amazon RDS

Amazon Relational Database Service (RDS) is a managed relational database service offered by AWS.

It supports database engines such as MySQL, PostgreSQL and other supported database systems.

It helps automate tasks such as backups and database maintenance.

3.16 Azure SQL Database

Azure SQL Database is a managed relational database service on Microsoft Azure.

It is based on Microsoft SQL Server technology and provides cloud-hosted database capabilities.

3.17 Google Cloud SQL

Google Cloud SQL is a managed relational database service provided by Google Cloud.

It supports database engines such as MySQL, PostgreSQL and SQL Server.

3.18 NoSQL Databases in Cloud Computing

NoSQL databases are databases designed to store and manage data using models other than the traditional relational table model.

They are useful for applications that need flexible data structures and scalable data storage.

Common types:

  • Document databases.
  • Key-value databases.
  • Column-family databases.
  • Graph databases.

3.19 Amazon DynamoDB

Amazon DynamoDB is a managed NoSQL database service provided by AWS.

It supports key-value and document data models and is designed for applications requiring scalable database access.

3.20 Azure Cosmos DB

Azure Cosmos DB is a globally distributed database service from Microsoft Azure.

It supports multiple data models and APIs for building distributed applications.

3.21 Google Cloud Firestore

Cloud Firestore is a NoSQL document database provided by Google Cloud and Firebase.

It stores data in documents organized into collections and supports application development.

4. Cloud Networking and DevOps

4.1 Cloud Networking

Cloud networking refers to the network infrastructure and services used to connect cloud resources, applications and users.

It allows communication between virtual machines, databases, applications and external users.

4.2 Cloud Networking Basics

  • Virtual networks: Logical networks created within cloud platforms.
  • Subnets: Smaller divisions of a network.
  • Routing: Directing network traffic between destinations.
  • Firewalls: Controlling network access.
  • DNS: Resolving domain names into IP addresses.
  • Connectivity: Connecting cloud resources to users and other networks.

4.3 Virtual Private Cloud (VPC)

A Virtual Private Cloud is a logically isolated virtual network created within a public cloud provider's infrastructure.

Users can configure network ranges, subnets, routing and security rules.

Example: Amazon Virtual Private Cloud (Amazon VPC).

4.4 Load Balancing

Load balancing distributes incoming network traffic across multiple servers or resources.

It helps prevent a single server from becoming overloaded.

Benefits:

  • Improves application availability.
  • Distributes workload.
  • Supports better performance.
  • Helps handle increased user traffic.

4.5 Auto Scaling

Auto Scaling automatically increases or decreases computing resources based on workload or defined conditions.

Example: An online shopping website may increase server capacity during a major sale and reduce it when traffic decreases.

4.6 Content Delivery Network (CDN)

A Content Delivery Network is a group of distributed servers that deliver web content to users from locations closer to them.

It can improve loading speed and reduce the distance data must travel.

Examples: Amazon CloudFront and other CDN services.

4.7 Introduction to DevOps in Cloud Computing

DevOps is a set of practices that combines software development and IT operations to improve the process of building, testing and delivering applications.

Cloud platforms provide resources that support DevOps automation and collaboration.

4.8 DevOps Principles

  • Collaboration: Development and operations teams work together.
  • Automation: Repetitive tasks are automated.
  • Continuous improvement: Processes are regularly improved.
  • Monitoring: Applications and systems are continuously observed.
  • Fast delivery: Software changes are delivered more frequently and reliably.

4.9 DevOps Practices

  • Version control.
  • Automated testing.
  • Continuous integration.
  • Continuous delivery.
  • Infrastructure automation.
  • Application monitoring.
  • Team collaboration.

4.10 Continuous Integration (CI)

Continuous Integration is a software development practice in which developers regularly combine their code changes into a shared repository.

Automated builds and tests help identify errors early.

Example: A developer commits code to GitHub and an automated workflow runs tests.

4.11 Continuous Delivery (CD)

Continuous Delivery is a practice in which software changes are automatically built, tested and prepared for release.

The software can be deployed to production when the required approval or release step is completed.

4.12 CI/CD Pipeline

A CI/CD pipeline is an automated sequence of steps used to build, test and deliver software.

Code → Build → Test → Package → Deploy → Monitor

Benefits:

  • Reduces manual work.
  • Finds errors earlier.
  • Improves software delivery speed.
  • Supports repeatable releases.

4.13 Infrastructure as Code (IaC)

Infrastructure as Code is the practice of managing and creating computing infrastructure using configuration files or code instead of manually configuring every resource.

Examples: Terraform, AWS CloudFormation and Ansible.

Advantages:

  • Repeatable infrastructure setup.
  • Faster deployment.
  • Version control for infrastructure configurations.
  • Reduced manual configuration errors.
